快速上手

  1. 打开 Netoff，开启保护。
  2. macOS 会请求允许网络扩展。打开系统设置 › 通用 › 登录项与扩展 › 网络扩展，打开 Netoff 的开关。如果 macOS 弹出关于过滤网络内容的提示，选择“允许”。
  3. 回到 Netoff，状态显示“保护已开启”。在“概览”页选择一种模式。

三种模式

  • 黑名单：除了被阻止的应用和地址，其余一律允许。在“应用”页把某个应用设为“阻止”。
  • 应用白名单：每个应用第一次联网前都需要批准。出现提示时，选择允许多久。
  • 域名 / IP 白名单：每个陌生的域名或 IP 都需要批准。在提示中可以只允许该地址、允许整个域名，或允许该应用的全部连接。在“应用”页把某个应用设为“允许”，表示完全信任，之后不再询问。
💡

批准提示从出现时开始倒计时 120 秒。如果没有回应，只会拒绝这一次连接，不会生成规则。

更习惯用文本编辑器？规则保存在一个可直接编辑的普通文件中，详见编辑规则文件。

疑难解答

状态一直显示“正在连接…”，或保护无法开启

请确认在 系统设置 › 通用 › 登录项与扩展 › 网络扩展 中，Netoff 的开关已打开。然后在 Netoff 中关闭再重新开启保护。如果仍无效，打开 设置 › 网络扩展 › 重新安装扩展，若 macOS 提示，请重启 Mac。

某个应用没有被阻止

请确认保护已开启（绿色），并且该应用在“应用”页被设为“阻止”，或在菜单栏面板中被关闭。阻止针对新的连接；已经建立的连接可能会保持到应用自己关闭它。有些应用会长时间保持连接。

切换模式后所有东西都连不上了

在白名单模式下，尚未批准的连接会等待回应。打开 Netoff 回应提示，或在菜单栏中切回黑名单模式。建议：先在“应用”页把浏览器等必需的应用设为“允许”。

看到“未知进程”或“已退出的进程”

某个程序发起连接后，在 macOS 告知 Netoff 它是谁之前就退出了。这对存活时间极短的进程来说是正常现象。

连接日志提示不可用

日志由网络扩展保存，因此需要开启保护才能查看。开启保护后重新打开“连接日志”标签页即可。

收不到通知

请检查 Netoff 设置中的“通知”，以及 系统设置 › 通知 中是否允许 Netoff 发送通知。每个被阻止的应用只会触发一次通知，重新允许再阻止后会再次提醒。

能和 VPN 或代理应用一起使用吗？

Netoff 在这台 Mac 上按应用过滤连接。使用 VPN 或代理应用时，它们自己的连接会显示在该应用名下。其他过滤工具可能产生意料之外的相互影响；如果发现异常，请先关闭其他工具，并告诉我们观察到的情况。

编辑规则文件

Netoff 把规则保存在一个可以直接打开和编辑的纯文本文件中：~/Library/Application Support/Netoff/rules.json。可以点击“应用”或“域名与 IP”页工具栏里的文档按钮打开，也可以在 设置 › 规则文件 中打开。保存文件后，Netoff 会立即应用新规则，无需重启。重新载入规则按钮可随时再读取一次。

示例

{
  "mode": "blocklist",
  "allowSystemServices": true,
  "allowWhenNoUI": true,
  "logRetention": "days7",
  "apps": [
    { "app": "com.apple.Safari", "action": "deny", "expires": null },
    { "app": "/usr/bin/curl", "action": "deny", "expires": "2026-10-20T18:00:00Z" }
  ],
  "hosts": [
    { "pattern": "*.example.com", "action": "deny", "app": null },
    { "pattern": "*", "action": "allow", "app": "com.google.Chrome" }
  ]
}

各个键的含义

键含义
mode"blocklist"、"appAllowlist" 或 "hostAllowlist"
allowSystemServices、allowWhenNoUItrue 或 false，对应 设置 › 白名单模式 里的两个选项
logRetention"off"、"days7"、"days14"、"days30"、"mb5"、"mb10" 或 "mb200"
apps[]每个应用一条规则。app 是 Bundle ID（如 com.apple.Safari）或应用的路径；action 是 "allow" 或 "deny"；expires 可选。name 和 path 是可选的标注。
hosts[]每个地址一条规则。pattern 可以是域名（example.com）、含所有子域名的域名（*.example.com）、IP 地址，或表示全部的 *。app 把规则限定给某个应用，null 表示所有应用。
  • 省略的键会使用默认值，所以只有 hosts 列表的文件也是有效的。
  • 日期写成 2026-10-20T18:00:00Z 这样（UTC）。用 null 表示永不过期。过期的规则会被自动移除。
  • JSON 不支持注释，末尾多余的逗号会被视为错误。
  • 想查某个应用的 Bundle ID，可在“终端”中运行 osascript -e 'id of app "Safari"'。
🛟

写错了也不会把自己锁在外面。如果文件无法读取，Netoff 会继续使用之前的规则，并指出错在哪里（例如 hosts[2].action），在文件重新有效之前不会改动它。

在应用中所做的修改也会写入同一个文件，两边始终一致，写入时 Netoff 可能会整理格式。如果删除了该文件，Netoff 会根据当前规则重新生成。大幅修改前，建议先备份一份。

卸载

  1. 在 Netoff 中打开设置 › 网络扩展 › 卸载扩展…。
  2. 如果还想删除数据，请先使用清除日志、清除报告和重置所有规则…（见隐私政策）。
  3. 退出 Netoff，把它移到废纸篓。
